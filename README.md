# Ранжирование русскоязычных поисковых результатов

Решение соревнования **AMML ranking competition 2026**. Для каждой пары «поисковый запрос — текстовый фрагмент» модель предсказывает числовую оценку релевантности. Кандидаты внутри запроса сортируются по убыванию оценки.

**Результат финальной модели v9: Public NDCG@10 = 0.950200.** Третий бейзлайн соревнования — 0.932861. Окончательная оценка проводится по Private Leaderboard и может отличаться от Public.

## Данные и предобработка

Используются исключительно конкурсные `train.csv` (31 530 размеченных пар для 3 042 запросов), `test.csv` (13 507 пар для 1 305 запросов) и `sample_submission.csv`. Целевая метка `relevance` бинарная: 0 или 1. В train — 8 168 положительных и 23 362 отрицательных примера. Среднее число кандидатов на запрос — около 10.

В данных обнаружены пропуски в заголовках и метаданных, а также неоднородные форматы числовых полей. Используется нормализация текста и безопасное преобразование чисел; недоступные значения обрабатываются без удаления кандидатов. Для длинных текстов строятся два представления: начало фрагмента и окно с предложениями, наиболее близкими запросу. Идентификаторы не используются как признаки модели.

## Метрика и валидация

Основная метрика — **средний по запросам NDCG@10**. Документы сортируются по `prediction` по убыванию, а при равенстве — по `id` по возрастанию. IDCG вычисляется по всем кандидатам запроса; для запроса без релевантных фрагментов вклад равен нулю.

Train/validation разделяются через `GroupShuffleSplit` по `query_id` (`VALID_SHARE=0.12`, `SEED=993`), чтобы документы одного запроса не попадали в обе части. Веса моделей и режимы текстового представления выбираются на validation; стабильность также проверяется на двух частях валидационных запросов.

## Финальный пайплайн

1. **Jina v3.5** (`jinaai/jina-reranker-v3.5`): listwise-ранжирование всех кандидатов одного запроса; проверяются текстовые представления и порядок подачи кандидатов.
2. **BGE + LoRA** (`BAAI/bge-reranker-v2-m3`): дообучение на позитивно-негативных парах из train с RankNet-loss и дополнительной pointwise-компонентой. Используются две эпохи, `MAX_LENGTH=320`, `LR=6e-5`, LoRA `r=16`.
3. **LambdaMART** (`LightGBMRanker`): обучение на 48 признаках, включая оценки Jina и исходной BGE, относительные ранги внутри запроса, лексические совпадения, числа, даты и метаданные статьи. Сравниваются конфигурации с 7 и 15 листьями.
4. **Выбор ансамбля** по NDCG@10 на отложенных запросах. После выбора выполняется предусмотренный финальной версией дополнительный проход обучения BGE на ранее отложенной размеченной части train. Его итоговое состояние не проверяется на новой независимой выборке.
5. **Inference:** формируется `submission.csv` с колонками `id,prediction` и всеми 13 507 строками в порядке `sample_submission.csv`.

## Промежуточные эксперименты

| Вариант | Public NDCG@10 | Результат |
|---|---:|---|
| v3: BERT и признаки ранжирования | 0.870580 | Недостаточное качество |
| v4: BGE + LoRA | 0.924589 | Улучшение после доменного дообучения |
| v5: Qwen3 + BGE | 0.912319 | Ухудшение |

В `solution.ipynb` оставлен полный исполняемый пайплайн **только выбранной v9**. История экспериментов приведена здесь, без отдельных тренировочных запусков в ноутбуке.

## Воспроизведение

**Среда:** Kaggle Notebooks, Linux, Python 3.13, GPU NVIDIA T4 x2 (`cuda:0`); Internet включён для первоначальной загрузки весов. Версии Python-пакетов указаны в `requirements.txt`. Ноутбук устанавливает нужные NLP-компоненты, не переустанавливая CUDA-сборку PyTorch из Kaggle.

1. Откройте соревнование Kaggle и создайте ноутбук; через **Add Input** подключите файлы `train.csv`, `test.csv`, `sample_submission.csv`.
2. Импортируйте `solution.ipynb`; выберите **GPU T4 x2**, включите Internet.
3. Запустите все ячейки (для независимого фонового запуска в Kaggle — **Save Version → Save & Run All**).
4. После выполнения заберите `/kaggle/working/submission.csv` и отправьте его на страницу соревнования.

**Ограничения:** сторонние размеченные датасеты не использовались при дообучении. Начальные веса Jina и BGE предобучены авторами на внешних данных; допустимость их использования следует сверить с правилами курса. Веса загружаются из модельных репозиториев (для Jina используется `trust_remote_code=True`; лицензия Jina — CC BY-NC 4.0). Ревизии внешних модельных репозиториев и образ Kaggle не закреплены по commit hash, поэтому точное побитовое повторение ранее полученного Public Score не гарантируется.
